## AOP(Aspect Oriented Programming)란?
AOP 관점 지향 프로그래밍으로 **스프링 3대 요소** 중 하나이다.
> 핵심 비즈니스 로직과 공통 부가 기능을 분리하여 코드의 모듈화를 높이는 프로그래밍 패러다임

메서드 동작 전 후 과정에 부가로직 처리를 하게되며 `Filter`,`Interceptor` 등과도 주로 비교된다.

- `Filter` : DispatcherServelt 전후 - 웹 컨테이너에서 관리
  - XSS방어,인코딩 변환처리,요청 인증,권한 체크 등 - 요청이 DispatcherServlet에 전달되기 전
- `Interceptor` : Controller 전후  - 스프링 컨테이너에서 관리
  - 로그인 체크,권한체크,프로그램 실행시간 작업,로그확인
- `AOP` : 메서드 동작의 전 후 과정에 부가로직 처리
  - 로깅,트랜잭션,에러처리

보통은 로깅,보안,트랜잭션 관리,성능 모니터링,예외 처리,데이터 검증,캐싱 등등 여러곳에 사용할 여지가 있지만 대표적인 예시는 아무래도 로깅이 대표적이다.

## AOP의 원리 
Spring AOP는 메서드 호출을 프록시 객체가 먼저 받도록 하는 방식으로 동작한다.

1. Spring 이 대상 객체를 빈으로 등록할 때 AOP적용 대상이면 프록시를 만들어둔다.(메서드 호출시마다 프록시 생성x)
2. 다른 객체가 해당 메서드를 호출하면 프록시가 호출을 받는다.
3. 프록시는 설정된 부가 동작을 실행하고 호출을 실제 대상 객체로 이어준다.
4. 대상 메서드의 반환값이나 예외는 다시 프록시를 거쳐 호출자에게 전달된다.

### 적용해보기

```java
@Aspect  
@Component  
public class LoggingAspect {  
    private static final Logger log = LoggerFactory.getLogger(LoggingAspect.class);  
  
    @Around("execution(* spring.lab.BankingService.*(..))")  
    public Object logExecution(ProceedingJoinPoint joinPoint) throws Throwable {         // 여기서 joinPoint는 AOP가 가로챈 메서드 실행지점이다
        String method = joinPoint.getSignature().getName();  
        long start = System.currentTimeMillis();  
	  
        try {  
            // 해당지점에서 가로챈 메서드 계속 진행 
            Object result = joinPoint.proceed();  
            log.info("{} 성공 {{}ms}", method, System.currentTimeMillis() - start);  
            // 원래 메서드를 호출한쪽(Ex.Controller) 에 결과를 돌려줌
            return result;  
        } catch (Throwable e) {  
            log.warn("{} 실패 ({}ms): {}", method,  
                    System.currentTimeMillis() - start, e.getMessage());  
            throw e;  
        }  
    }  
}
```

> AOP기반 기술로는 `@Transactional` 외에도 `@Async`,`@Cacheable`,`@PreAuthorize` 등등 많이있다.
## `@Transactional` 

데이터베이스 트랜잭션을 선언적으로 관리하기 위해 사용하는 어노테이션

#### 순수 JPA - 트랜잭션 직접 관리 
```java
public class TransferService {

    private final EntityManagerFactory emf;

    public TransferService(EntityManagerFactory emf) {
        this.emf = emf;
    }

    public void transfer(Long from, Long to, int amount) {
        EntityManager em = emf.createEntityManager();
        EntityTransaction tx = em.getTransaction();

        try {
            // 트랜잭션 시작
            tx.begin();

            Account sender = em.find(Account.class, from);
            Account receiver = em.find(Account.class, to);

            sender.withdraw(amount);
            receiver.deposit(amount);

            // 변경 감지 및 커밋
            tx.commit();

        } catch (RuntimeException | Error e) {
            if (tx.isActive()) {
                tx.rollback();
            }
            throw e;
        } finally {
            em.close();
        }
    }
}
```

`try-catch`문과 `begin()`,`commit()` 을 사용하며 코드가 지저분 + **중복 코드 작성** 이 보인다.

#### @Transactional을 적용하면?
```java
@Service
public class TransferService {

    @PersistenceContext
    private EntityManager em;

    @Transactional
    public void transfer(Long from, Long to, int amount) {

        Account sender = em.find(Account.class, from);
        Account receiver = em.find(Account.class, to);

        sender.withdraw(amount);
        receiver.deposit(amount);
    }
}
```

위와같이 `try-catch`문과 `begin()`,`commit()`코드가 사라져 아주 깔끔해진다.
> 여기에 Spring Data JPA가 제공하는 `JpaRepository` 인터페이스를 활용하면, `EntityManager`를 직접 사용하지 않고도 데이터 접근 로직을 구현할 수 있다

이러한 이유는 Spring AOP 프록시와 `TransactionInterceptor`가 `JpaTransactionManager`를 통해 트랜잭션을 관리하기 때문이다.

### `@Transactional`의 내부 동작

그렇다면 `@Transactional`은 내부적으로 어떻게 동작할까?

먼저 Spring AOP 프록시가 메서드 호출을 가로채고, 해당 메서드에 적용할 인터셉터 체인을 조회하여 실행한다.
이때 `@Transactional`이 적용되어 있다면 `TransactionInterceptor`의 `invoke()`가 실행된다.

```java
@Override
public Object invoke(MethodInvocation invocation)
        throws Throwable {

    // ... 생략

    return invokeWithinTransaction(
        invocation.getMethod(),
        targetClass,
        // ... 생략
    );
}
```

이후 부모 클래스인 `TransactionAspectSupport`의 `invokeWithinTransaction()`이 호출되며, 트랜잭션 관리 로직이 실행된다.

이 과정에서 실제 트랜잭션 매니저가 `JpaTransactionManager`이고 새로운 트랜잭션을 시작해야 한다면 `doBegin()`이 호출된다.
```Java
@Override
protected void doBegin(
        Object transaction,
        TransactionDefinition definition
) {
    JpaTransactionObject txObject =
            (JpaTransactionObject) transaction;

    try {
        // 1. 트랜잭션에서 사용할 EntityManager 생성
        if (!txObject.hasEntityManagerHolder() ||
                txObject.getEntityManagerHolder().isSynchronizedWithTransaction()) {

            EntityManager newEm = createEntityManagerForTransaction();

            txObject.setEntityManagerHolder(
                    new EntityManagerHolder(newEm), true
            );
        }

        EntityManager em =
                txObject.getEntityManagerHolder().getEntityManager();

        // 2. 실제 JPA 트랜잭션 시작
        int timeoutToUse = determineTimeout(definition);

        Object transactionData = getJpaDialect().beginTransaction(
                em,
                new JpaTransactionDefinition(
                        definition,
                        timeoutToUse,
                        txObject.isNewEntityManagerHolder()
                )
        );

        txObject.setTransactionData(transactionData);

        // ... 생략

        // 3. EntityManager를 현재 스레드에 바인딩
        if (txObject.isNewEntityManagerHolder()) {
            TransactionSynchronizationManager.bindResource(
                    obtainEntityManagerFactory(),
                    txObject.getEntityManagerHolder()
            );
        }

        // ... 생략
    }
    // 예외 처리 생략
}
```
`doBegin()`은 JPA 트랜잭션을 시작하기 위한 작업을 수행하며, 이후 비즈니스 메서드 실행 결과에 따라 커밋 또는 롤백이 처리된다 => 개발자가 직접 작성했던 트랜잭션 시작 로직을 Spring이 대신 처리하는 것이다.
